# Supported sites

**Fully compatible sites: none.** No site has passed end-to-end testing for automatic updates and safe refresh behavior. The entries below record evidence from publicly inspected responses/pages and repeatable parser fixture tests; they are not compatibility claims.

The fixture tests are offline unit tests over sanitized excerpts of public responses. They do not prove that the live pages or API remain unchanged, that every series uses the same layout, or that background monitoring works. No chapter data from a failed, partial, blocked, or dynamic response is treated as an empty successful list.

## Implemented discovery methods

- Generic HTML title and metadata extraction, including Open Graph, Twitter metadata, canonical links, and selected JSON-LD/Schema.org objects (`Article`, `CreativeWork`, `Chapter`, `Manga`, `CreativeWorkSeries`, and `ItemList`).
- A conservative fallback scans public static HTML for at least three same-host chapter links belonging to the same inferred series path. It excludes common navigation/related-content links and accepts a recent window only when chapter numbers or publication dates are strictly ordered. This identifies a latest chapter, not a complete archive. A synthetic offline fixture covers relative links, route variations, unrelated links, and an out-of-order rejection; no arbitrary live site is certified by this test.
- WordPress-style post slugs ending in a chapter identifier are grouped by the series-name prefix, rather than by a shared parent path. Decimal suffixes using a hyphen are normalized for ordering, while list labels remain authoritative when available.
- WordPress recognition as a platform hint only; no theme-specific selectors are assumed.
- Independent parser registry and HiveToons chapter/series adapters for the observed HTML and serialized stream format. A verified newest-first window is sufficient for tracking forward; it is not treated as a complete historical archive.
- A site-specific Imperio da Britannia adapter for its observed public JSON endpoint, with bounded HTTPS fetching, public-address validation, DNS pinning, response-size limits, redirect refusal, slug/ID validation, and partial-window handling.
- A site-specific RoliaScan adapter for its public chapter endpoint, with bounded HTTPS fetching, public-address validation, DNS pinning, response-size limits, redirect refusal, series-slug/ID/ordering validation, and recent-window handling.
- A Mairimashita Iruma-Kun adapter for the observed static series page. Recognized chapter URLs are read from the series page so registration uses its latest visible chapter as the baseline; the saved list remains a partial recent window.
- Manual CSS and bounded RE2/J regex rules with URL resolution, preview/test, and per-host Room persistence. A configuration can be saved only after it succeeds against fetched HTML.
- Safe static HTML fetching with public-address validation and DNS pinning, response-size/time limits, conservative redirects, and explicit outcomes for access denials, unavailable pages, non-HTML responses, and network failures.

These features provide discovery and a manual setup path, not guaranteed compatibility with arbitrary sites. The generic fallback requires identifiable chapter labels/URLs and a stable ordering signal. JavaScript-only pages remain unsupported unless the needed information is available through a permitted static response or a specifically supported public endpoint.

## Requirements before claiming full support

1. Recheck that the page is public and that the intended access complies with its terms, policies, and rate limits. Never bypass login, paywalls, CAPTCHA, or other controls.
2. Test the actual page types claimed in the entry using the implemented parser.
3. Validate title, original cover, series page, chapter identifiers, dates, links, and list completeness against observed content. Record missing fields and limitations.
4. Add sanitized offline fixtures and repeatable tests for normal, missing-field, changed-markup, and failure cases.
5. Demonstrate that incomplete/error results do not replace the last valid snapshot or imply that no new chapters exist.
6. Record the test date, scope, parser, and exact evidence here. Re-test when the source or parser changes.

Do not treat metadata presence, a WordPress signature, one fixture, or manual configuration alone as proof of full site compatibility.
