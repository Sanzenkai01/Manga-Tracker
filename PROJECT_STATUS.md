# Project status

**Last updated:** 2026-11-17

**Opening animation (2026-11-17):** System splash and a Compose icon overlay are implemented for cold launcher starts when system animations are enabled; notification launches and recreated activities do not restart the entrance. The splash waits for the persisted theme preference up to 600 ms to avoid a light frame before a dark app theme. `:app:testDebugUnitTest`, `:app:lintDebug`, and `:app:assembleDebug` passed (72 JVM tests, no failures). No Android device/emulator was connected, so visual validation on Android 8–11 and 12+ remains unverified.

**Large cover images (2026-11-16):** Two Império da Britannia PNG covers were verified to return HTTP 200 with sizes of 12.3 MB and 18.0 MB; the app's image client previously rejected responses above 2 MiB. Image loading now streams responses within a 20 MiB cap and allows longer transfer timeouts. Core data tests, app lint, and debug assembly passed; rendering on the user's device remains unverified.

**Império da Britannia numeric routes (2026-11-16):** Numeric manga paths such as `/manga/1454/capitulo/185` now use the public API's by-ID endpoint and validate the returned work ID; slug paths continue using the by-slug endpoint. The public API response for ID 1454 was verified to identify "Vingança do Cão de Caça dos Baskerville" and return 189 chapters. Parser/fetcher tests and a debug build passed; in-app refresh remains unverified.

**CI and release preparation (2026-11-16):** Added a GitHub Actions workflow for the requested JDK 17 test/lint/debug-build matrix; the workflow makes `gradlew` executable without changing its tracked Git mode. Release minification and resource shrinking are enabled, and an adaptive launcher icon with a monochrome layer is configured. Android cloud backup and device transfer are explicitly disabled; the app's manual JSON backup remains available. The requested CI matrix, `:app:assembleRelease`, and post-policy debug/release builds and lint completed successfully locally; the release APK is unsigned. The tracked source ZIP and root PNG remain untouched pending approval.

**Notification grouping (2026-11-16):** A single new chapter keeps the existing notification. Two or more chapters detected for one manga in the same check are delivered as one cover-capable notification with the newest chapter link and a list-scoped “mark as read” action. The publisher returns every chapter ID in a posted group for delivery timestamps; canceling one chapter updates the group (or converts the last one to a single notification), while removing a manga still cancels its notifications. The general summary remains limited to two or more distinct manga.

**Recent change:** The monitoring interval is configurable in Settings (1, 3, 6, 12, or 24 hours), persisted in DataStore, and applied to the unique periodic WorkManager request. The default remains one hour, with existing network/battery constraints and Android scheduling caveats. Monitoring health is derived from persisted check attempts without a Room migration. Five consecutive eligible server/parse failures, or more than three days since a successful check when an eligible site failure exists, marks an actively monitored manga as having a problem. Network-only failures do not count. The library/details display the state, and a dedicated notification channel is deduplicated by episode in DataStore. The library also has a Material 3 pull-to-refresh gesture and an "Update all" action for monitored manga; the existing coordinator checks them asynchronously and reports successful and failed counts.

**Parser addition (2026-11-15):** `:core:parser-engine` now recognizes same-host RSS/Atom alternate links and WordPress `/feed/` as a clue. It parses supplied feed XML into a verified recent window using the existing `ParsedSitePage` contract. Empty, missing, truncated, partially parsed, or unordered feed content stays `RequiresConfiguration`; it is not an empty successful result. Fetching the feed over the network and live-site validation are not part of this stage.

**Overall state:** The selectable theme and app language follow the system by default. Brazilian Portuguese resources and English fallback are available. The library has read/unread filters, color-coded status badges, multi-select actions, and accessible icon-only top-bar actions. Versioned JSON backup export and non-destructive import are implemented; import merges into the local library and preserves current records on conflicts. Generic discovery checks static HTML for an ordered recent chapter window; HiveToons, Mairimashita Iruma-Kun, Imperio da Britannia, and RoliaScan have site-specific parsing support. Automatic checks use the same site-specific fetchers as discovery. When a saved manga page yields metadata, manual and automatic checks now fill missing title, original cover URL, and same-host series URL without replacing existing values; this also applies when the chapter list is incomplete. Newly found chapters remain queued for notification if Android permission/channel settings prevent delivery, then are retried after a later successful check. Site/parse monitoring problems are derived from attempt history and use a separate, once-per-episode notification channel; network-only failures are excluded. RoliaScan's observed public chapter endpoint and cover are integrated and fixture-tested, but not verified in-app. For Imperio da Britannia, the fetcher now sends the plaintext-response header exposed by the site's public client; the supplied API sample returned 186 chapter rows and its cover loaded in a browser. Its declared chapter count conflicts with the response, so the list is not marked complete. In-app refresh and device rendering remain unverified.

## Implemented

- Gradle Kotlin DSL project with `:app`, `:core:domain`, `:core:data`, `:core:parser-api`, `:core:parser-engine`, and `:parsers:site-adapters`.
- Configured Kotlin 2.1.21, AGP 8.10.1, Gradle 8.11.1, JDK 17, `minSdk` 26, and SDK 35. The dependency set includes Compose/Material 3, Room, WorkManager, OkHttp, Jsoup, Coroutines/Flow, Navigation Compose, Coil, and DataStore.
- Android application, Compose theme, initial library screen/navigation/ViewModel, an “Add a manga” entry point, and a manual dependency container.
- Room schema v3 for manga, chapters, current reading state, append-only reading history, per-host parser configuration, individual monitoring settings, check attempts, and pending chapter notifications.
- Non-destructive Room migrations v1→v2→v3 preserve existing records; v1→v2 renames the parser-configuration and monitoring tables and adds a chapter ordering index, while v2→v3 adds the pending-notification queue.
- `RoomMangaRepository` workflows for persistence/observation, idempotent chapter reconciliation, unread counts, configurations, monitoring state, and check attempts.
- Parsed manga metadata is also applied during manual and automatic checks: blank title, original cover URL, and same-host series URL fields are filled for existing or restored records. Existing nonblank metadata is preserved, and this update can occur even when the chapter list is incomplete.
- Library summaries expose the count of unread chapters detected by the most recent successful check, using persisted chapter detection times and read state; this is a query projection change and does not alter the Room schema.
- Room projects monitoring-problem signals from `check_attempt` without changing the schema. Only server-response and parser failures after the most recent success count; `MonitoringProblemSignals` applies the five-failure and stale-success thresholds. The library badge and manga-detail explanation are gated by active monitoring.
- Site-problem notification episodes are claimed atomically in the existing DataStore preferences, which prevents hourly checks from repeating the same alert. The notification publisher uses a dedicated channel and clears the active alert after a successful check.
- New chapters start unread. Refreshes update chapter metadata without changing existing read state. Only explicit read/unread actions change that state, and actual transitions record history transactionally.
- `ValidatedChapterSnapshot` rejects unverified incomplete parser results before persistence; a separate verified-recent-window snapshot is used only after safe baseline comparison. A complete empty snapshot does not delete previously stored chapters.
- DataStore repository for list/grid, theme, and monitoring interval preferences. Theme defaults to following the device and persists `SYSTEM`, `LIGHT`, or `DARK`; the monitoring interval defaults to one hour.
- `SafeHtmlFetcher` uses OkHttp with public-address validation and pinned DNS results, same-host redirects only, no HTTPS downgrade, standard ports, HTML/content-size limits, timeouts, and explicit network/access/page/response errors.
- `SyndicationFeedParser` recognizes same-host RSS/Atom alternate links and WordPress `/feed/` hints, parses RSS item and Atom entry titles/links/dates from supplied supplemental data, filters entries to the series, and validates ordering before marking a latest-known window. Empty, truncated, partially parsed, or unordered feeds remain an incomplete parse; feed fetching is not yet integrated.
- `SafeJsonFetcher` applies an explicit API-host allowlist, HTTPS/443 production policy, public-address validation with pinned DNS, no redirects, JSON media-type validation, timeouts, and a bounded response size. Optional request headers are scoped to explicit allowlisted hosts; Imperio's instance sends the plaintext-response header used by its public client.
- Parser API and independent registry; generic extraction supports Open Graph, HTML metadata, selected JSON-LD/Schema.org types, canonical URLs, date hints, WordPress indicators, and dynamic-shell detection. A chapter list is complete only when structurally validated or manually configured and tested.
- Generic static-HTML discovery can identify a newest chapter from at least three same-host links grouped by inferred series path when chapter numbers or dates form a strict sequence. Navigation/related links are filtered, links are normalized, and the result remains a partial recent window. It does not guarantee support for arbitrary sites or JavaScript-rendered lists.
- WordPress chapter-post slugs such as `/manga/series-name-chapter-443-5/` retain their series-name prefix during grouping and series URL derivation. Hyphen-separated decimal numbers are normalized for comparison; link labels remain the displayed chapter identity.
- `HiveToonsArticleParser` uses observed JSON-LD/Open Graph fields from the supplied Eleceed sample. Its fixture test validates title, cover, series URL, chapter, and date while confirming that the chapter list is incomplete.
- `HiveToonsSeriesParser` validates a newest-first recent window from chapter links and any serialized records delivered with the page; a declared historical count is not required to track forward, and unrelated links in the chapter panel do not invalidate that window. The full historical count is required only to mark the archive complete. It rejects malformed, duplicate, mismatched, or out-of-order records and retains page-row labels/dates when available. Offline fixtures cover partial windows with/without declared counts, unrelated panel links, out-of-order windows, invalid number/slug pairs, decimal identifiers, and a 427-record payload.
- For a verified recent window, registration stores only the latest chapter as the initial baseline. Later checks compare saved source keys first; if a site changes keys, pure domain rules compare marker-prioritized numbers and persist only higher numbered chapters. Unnumbered extras are ignored by numeric fallback but remain included in source-key comparisons. If no baseline can be established, no chapters are changed. Generic incomplete results remain non-persistable.
- The Imperio da Britannia page's static HTML remains a JavaScript-rendered shell. The site's public client defines the `X-NoEncryptionBritta: 1` header for plaintext API responses; the app now sends it only to the allowlisted API host, without executing site JavaScript or decoding encrypted responses. A live browser request for the supplied chapter-185 sample returned JSON with chapters 1–186, including 185 and 186, plus the CDN cover path. The response declares 148 chapters, so the parser does not mark the list complete. The cover loaded in a browser at 2667×4000. App/device behavior remains unverified.
- `RoliaScanDocumentFetcher` resolves chapter links to the same-host series page, reads the public `data-manga-id`, and requests up to 500 chapters from the site's unauthenticated list endpoint. `RoliaScanParser` validates the newest-first window and the series cover URL; chapter registration saves only the current latest as baseline, while future checks reconcile only a verified delta. The observed sample returned 286 rows and its cover URL returned HTTP 200 `image/jpeg`. The site's own script notes per-IP abuse limits; the app makes one bounded request per check and does not fetch another page. Live in-app and device behavior remain unverified.
- The observed Mairimashita Iruma-Kun root page exposes a static chapter list and title-labeled cover images. `MairimashitaIrumaKunDocumentFetcher` resolves recognized chapter links against that root before registration so the newest visible chapter seeds monitoring. `MairimashitaIrumaKunParser` extracts its ordered recent window and original matching cover; fixtures cover the observed structure and a decimal chapter slug. The list is deliberately not marked as a complete archive. Live in-app addition and monitoring remain unverified.
- The add-manga screen shows only the identified title and chapter. Manual site setup stays collapsed until requested; when opened, it offers title, cover, series URL, chapter number, date, chapter link, CSS selector, and RE2/J regex rules. Configurations are normalized and saved by hostname only after a successful test against fetched HTML.
- The manga-link field includes a localized Paste action. Settings sections are separated by dividers; existing preferences and actions are unchanged.
- Library supports responsive list/grid layouts, persists the selected layout with DataStore, and keeps manga cards to a compact chapter/unread summary with Coil image loading. Verification and monitoring details remain available in manga details.
- The library can filter all manga, those with unread chapters, or those whose saved chapters are all read. Each manga has a status badge in list and grid layouts: green for newly detected unread chapters, red for other unread chapters, and blue when all saved chapters are read. The badge shares its colors and rendering with chapter details.
- Long-press selection in either library layout supports batch read/unread actions and confirmed removal. Read-state changes and history are written transactionally; removal deletes only selected manga and their chapters, reading history, monitoring settings, and check attempts, then cancels their scheduled checks and active notifications.
- Registration requires an identified title, series URL, and current chapter. A verified recent window seeds only the latest chapter, so a site does not need to expose its historical archive. Monitoring updates require either a complete list or a verified newest-first window that can be compared safely with saved chapters. Partial or ambiguous results do not overwrite saved data. Registration uses the Room repository and detects duplicate series.
- Manga details expose chapter links and separate read/unread controls. Opening a chapter launches its URL without changing the saved reading state.
- Manual per-manga and automatic refresh use the bounded HTML fetcher and registered parsers; unverified incomplete lists have a distinct outcome from network/parsing failures and do not reach reconciliation. Library-wide manual refresh sequentially checks only actively monitored manga through the existing coordinator and reports successful/failed counts. A verified newest-first window reconciles only the safe delta after the saved baseline.
- WorkManager monitoring schedules one periodic dispatch at the selected 1/3/6/12/24-hour interval (one hour by default, 15-minute flex window), then unique checks for enabled manga. Changing the option updates the unique periodic work; the saved interval is restored at startup. Network connectivity and battery-not-low constraints apply; per-manga work uses exponential retry backoff starting at 30 minutes.
- New manga start with monitoring enabled and receive an automatic check after registration. Individual pause persists the disabled state and cancels that manga's automatic work; workers recheck the setting before fetching and saving. Manual refresh remains available while paused.
- Automatic checks share the registered site-fetcher chain used for discovery (HiveToons, Mairimashita Iruma-Kun, Imperio da Britannia, RoliaScan, then the bounded generic HTML fetcher). Previously paused manga remain paused to respect the saved choice; re-enable monitoring in that manga's details to resume checks.
- Check coordination serializes checks per manga, limits automatic requests to the same host to one per two seconds in-process, uses the saved same-host series URL for automatic checks unless a manual page configuration is active, records success/failure/incomplete outcomes, and only reconciles complete lists or verified recent-window deltas. Network, rate-limit, and server failures are retryable; access/configuration/parsing failures do not erase existing chapters.
- The app restores the unique periodic schedule and saved interval at startup. The UI warns that Android may defer checks; WorkManager does not guarantee execution exactly at the selected interval.
- Settings exposes persisted layout, theme, and automatic-check interval choices, the site configuration entry point, and a plain-language explanation of automatic search timing. The layout selector is a compact Material 3 segmented control; theme modes and five interval options are grouped, selectable rows in cards. Settings content scrolls on shorter screens. Interface and dynamic parser/fetch messages follow the system language (pt-BR resources, English fallback); date/time presentation follows the system locale. Externally sourced manga/site names remain unchanged.
- Settings can save a versioned JSON backup or select one to load through Android's document picker; no broad storage permission is required. Imports validate the complete format first and merge manga, chapters, read state/history, monitoring/check data, and site configurations transactionally. Existing manga metadata, chapter state, monitoring preferences, and site configurations are preserved on conflicts, and repeated imports do not duplicate history or checks.
- Discovery cancels/invalidate prior fetch and manual-test jobs when the URL or manual rules change, preventing stale asynchronous results from being applied.
- JSON-LD input now has script, aggregate-size, depth, and structure limits. An `ItemList` is not treated as complete unless its declared item count matches the valid unique entries.
- Chapter metadata refreshes preserve an already-known publication date when a new parse omits it; chapter and latest-manga ordering use a stable numeric tie-breaker.
- Coil's application-wide image loader uses a public-host-validated OkHttp client with scheme, credential, port, timeout, and response-size checks; notification cover fetching retains its separate bounded path.
- Library and detail screens expose the persisted outcome of the last check; partial source lists are identified as a limitation rather than displayed as a generic failed check.
- Chapter cards distinguish read (blue), newly detected (green), and unread (red) states, and the detail header no longer repeats the manga title beside the cover.
- The application manifest now points to the existing project artwork as its launcher icon. Notification grouping uses plural resources, and API guards impossible under `minSdk 26` were removed.
- Chapters newly discovered during a successful manual or automatic check are queued transactionally before notification delivery; registration baselines and restored backup chapters are not queued. Pending items survive process restarts and are retried at the next successful check if Android permission/channel settings previously blocked delivery. They are cleared after successful posting or an explicit read transition, and cascade-delete with their chapter.
- Chapter notifications include the original manga cover when safely fetched, manga title, chapter label, source host, and first-detected time; BigPictureStyle is used with a text-only fallback. Multiple active updates across different manga are grouped.
- Open actions use an immutable ACTION_VIEW PendingIntent and do not touch reading state. The independent mark-read action targets a non-exported receiver and applies the explicit Room read transition/history action. Successful delivery timestamps are stored idempotently; new chapters remain unread.
- A stable notification channel is created on startup. Android 13+ `POST_NOTIFICATIONS` is requested only after the user selects Enable in Settings; blocked permissions/channels are reported and not bypassed.
- Notification covers use bounded public-host-validated HTTP fetches, same-host redirects, and downsampled bitmap decoding off the main thread; Coil requests use the bounded public image client.
- Notification-specific Robolectric tests cover channels, content and cover, immutable actions, grouping, denied permission, and the explicit read action. Android resources are enabled for these tests; the WorkManager scheduler test uses a neutral Application to avoid starting production WorkManager during setup.
